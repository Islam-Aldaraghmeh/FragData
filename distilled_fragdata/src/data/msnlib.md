# MSnLib parsing and linkage

Purpose: stream the existing line-delimited MSnLib exports, preserve physical scan
identity and acquisition paths, and enumerate every compatible MS2 peak for an MS3
observation. This module uses only the Python standard library.

## API and inputs/outputs

- `physical_scan_identity(raw)` returns physical scan identifiers and explicit
  issues. Source scan USIs take precedence over library accession USIs; raw file
  and scan annotations are cross-checked, including exported scan ranges.
- `canonical_metadata(raw, source_path=..., source_row=..., source_sha256=...)`
  returns the prototype metadata dictionary. Singleton exported CE lists and
  nested paths are handled exactly as before. Invalid or ambiguous paths retain
  their issues. Molecular formula, SMILES, charge and precursor m/z at the top of
  an export remain *parent* annotations.
- `iter_metadata(path, ms_levels=(2, 3), individual_only=True,
  include_ms2_peak_mzs=False)` streams JSON records one per line, even when the
  filename ends in `.json`. Optional MS2 peak masses avoid reopening rows during
  linkage. The whole source is hashed once for provenance, then streamed.
- `load_source_row(metadata)` / `load_peaks(metadata)` reopen the exact source row
  and verify the source and row hashes by default. Source files must remain
  available at their recorded locations.
- `link_ms3(child, parents, mz_tolerance=0.01)` returns the original result
  dictionary with all compatible peaks, indices, masses, source aliases and
  linked isolation IDs. Parent scans must precede the child and share feature,
  raw file, ancestor energy path and compatible precursor path.
- `link_status(result)` returns `unique`, `ambiguous`, `unresolved` or
  `conflicting`. It maps original `annotation_conflict` to `conflicting` and
  `invalid_child_metadata` to `unresolved` without altering `result["status"]`.
- `isolated_fragment_mz(metadata)` and `ms3_collision_energy(metadata)` read
  canonical isolated-stage values. They return `None` when parsing could not
  establish a value; they do not infer missing values from the parent.
- `nce_to_msg_scalar(nce, fragment_mz)` returns `float(nce) * float(fragment_mz)
  / 500`. For MS3, pass the isolated fragment m/z.
- `group_ms3_energies(observations)` returns `{isolation_id: {CE: [rows]}}`, using
  `linked_isolation_id` when present and the acquisition path ID otherwise.
  Every replicate and every group is retained. Grouping does not validate links.

## Example

```python
from src.data.msnlib import (
    iter_metadata, link_ms3, link_status, load_peaks, nce_to_msg_scalar,
)

rows = list(iter_metadata("small_export.json", include_ms2_peak_mzs=True))
parents = [r for r in rows if r["ms_level"] == 2]
child = next(r for r in rows if r["ms_level"] == 3)
result = link_ms3(child, parents)
if link_status(result) == "unique":
    linked_peak = result["matches"][0]
    experimental = load_peaks(child)
    model_ce = nce_to_msg_scalar(child["collision_energy"], child["isolated_mz"])
```

## Prototype sources and equivalence

`fragment_glacier_pretrained_adapter/src/ms3_data.py`: all private parsing
helpers, `physical_scan_identity`, `ce_provenance`, `canonical_metadata`,
`_hashed_source`, `source_sha256`, `iter_metadata`, `load_source_row`, `load_peaks`
and `link_ms3` are preserved directly. No donor controls, cohort selection,
annotation audit framework, manifest or resume system was copied. The parser
and linker are longer than the suggested 250-line module target because retaining
all original metadata and conservative link checks avoids changing behavior.

CE arithmetic is extracted from the `nce_fragment_mz_convention` branch of
`run_ms3_exploratory.model_ce`; it returns that branch's Python scalar. GLACIER's
input layer remains responsible for its original float32 conversion.

`tests/test_msnlib.py` compares complete canonical records and link dictionaries
to frozen outputs generated by the original implementation. When the prototype
is present it also compares the live original functions, source loading and
peaks. Fixtures cover unique, multiple-parent, multiple-peak, unresolved,
annotation-conflict, spectrum-conflict, invalid-child and duplicate-alias cases.

Intentional wrapper changes: the friendly status and stage accessor functions
are new conveniences. Energy grouping retains all replicates and singleton
energy groups; the old `prepare_ms3_exploratory.main` selected one scan per energy
by hash and required at least two energies for its specific analysis. That
selection was deliberately not transferred to this general data loader. Parsing
and linkage scientific behavior are unchanged.

## Scientific hazards

Compatibility with an exported acquisition path and peak is not proof of a raw
`spectrumRef` parent-child relationship. Never select the first match unless the
original status is `unique`. Duplicate physical spectra with conflicting
annotations or peak data remain conflicts, including when only one distinct
peak matches. A fallback acquisition-path group is not a unique linked peak.

Top-level formula and charge never establish the isolated MS3 ion's formula and
charge. A stage charge requires an explicit exported stage annotation. NCE
conversion is the MassSpecGym preprocessing convention, **not** proven physical
ID-X calibration. Historical collection CE provenance labels are preserved;
their referenced evidence files belong to the original prototype and are not
bundled here. Unknown collection units remain unresolved.
